# Terminal workspace design

The additive `/workspace` client frames shared daemon-owned terminals. `/legacy` remains the browser baseline. The desktop workspace and dedicated Android document share the terminal protocol and session identities. Unified relay account controls described below are currently implemented in the Windows/browser workspace.

Visual reference: `study/orca/docs/STYLEGUIDE.md` and `study/orca/src/renderer/src/assets/main.css`. Quiet neutral surfaces, thin borders, restrained selection, compact chrome. No terminal output recoloring. System Segoe UI avoids introducing a font dependency; Cascadia/Consolas serve terminal text.

Layout: project/host/session sidebar, compact tabs, a binary resizable split tree, one active pane, and a status footer. On phones, only the active terminal renders; switching open tabs preserves terminal parser state. Closing a view releases its parser, observer and GPU resources; reopening requests bounded history. A drawer exposes projects. Esc, Tab, Ctrl and arrow keys are reachable above the footer.

Closing a tab detaches its view. Ending a shell is a separate explicit destructive action. Terminal size follows an explicit server lease; viewers can request control. Saved relay URL/code are local; access tokens default to tab session storage, with explicit opt-in device persistence.

Rendering is independently selectable as auto, DOM or WebGL. Unicode11 is enabled in either mode when supported. WebGL context loss falls back to DOM with visible diagnostics. Reconnect requests bounded output history; it does not claim exact arbitrary VT screen restoration.

Window identity: right-click a tab, pane title or sidebar window label to rename it or select one of seven text/background swatches. Both frontends share the palette and menu. Themes apply to window labels only; terminal output retains its original colors. The active tab keeps a contrasting top marker. The daemon owns the theme alongside the window title and broadcasts changes to all connected views; browser refresh retains it while the window exists. Restoring the default palette is an explicit menu action.

Sidebar window activity: each desktop session row reserves an 8px red/yellow/green status lamp before its label, indented 12px farther than the earlier layout beneath the owning group. Red means the host is disconnected; yellow means no recent live output; green pulses while live output has arrived within 1.8 seconds. Snapshot replay does not count as live activity. Lamps have a dark outline for themed labels, status tooltips/accessibility names, and no animation under reduced motion. Activity is scoped to the owning host/session and observed existing subscriptions; adding lamps does not subscribe unopened terminals or infer an agent's execution/completion state.

Local attachment: new clients reuse the default daemon on 6769 and initially open every existing session as a tab. A separate loopback frontend supplies current assets while forwarding byte streams to that same daemon; it never recreates PTYs. It advertises its backend and UI revision so launchers can reuse it. Older daemons retain titles/PTY ownership, with a local frontend overlay for unsupported label colors; newer daemons advertise `window_themes` and remain authoritative for colors as well. Closing a frontend view only detaches it.

Computer workspaces: the sidebar's top plus opens a named computer connection with relay address, room code and authentication mode. Each computer maintains an independent transport and catalog; choosing a computer does not disconnect the other computers. JSON tuple keys isolate colliding session IDs, and asynchronous callbacks capture host generations. Manual tokens are scoped to each saved computer and remain in session storage unless persistence is explicitly selected. A home entry returns to the original local connection. Removing a saved computer removes the connection record, not its terminals.

Unified relay account: both connection dialogs offer a centrally configured relay suggestion and free entry. A separate account panel logs into an HTTPS/WSS relay; account-scoped directory subscription fills authorized computer address/port, room, name and masked session credential. Session secrets are endpoint-bound and stored only in sessionStorage, while saved host metadata stores only account/manual mode. Account sessions never travel to daemon HELLO. A different account ID clears previous views/catalog/credentials before new authorization responses arrive; refreshing the same account may preserve terminal parsers. Global host administration remains local-owner-only, while delegated account access requires explicit host-local owner binding. Public plaintext login fails before credentials are sent. See docs/relay-account-setup.md for deployment prerequisites.

Android mobile document: the selector separates saved computers, current machine/project, grouped windows and sessions, and search. Its default sizing mode requests the mobile viewport grid from the server; local parser dimensions change only after server confirmation. Shared-original-size mode scales the canonical server grid and never automatically resizes it. Snapshot bytes wait for their session's first size metadata. Cold replay and output batches retain grid boundaries. Native connection home exposes APK/build/UI revisions, connection testing and recent changes. USB UI updates are complete hashed snapshots; native upgrades remain APK operations. Evidence and maintenance commands: `docs/android-live-updates.md`.
