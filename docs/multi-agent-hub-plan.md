# Multi-Agent Hub 分阶段实施计划

本页是 SuperMonoAgent 端的回归与联调清单。跨仓库目标、实施顺序与最终验收统一见[项目目标与执行总计划](https://github.com/gaoxingkele/mylib/blob/main/tools/agent-hub/rollout-design.md)。产品架构见 [驾驶舱架构](multi-agent-hub.md)，双端行为见 [DESIGN.md](../DESIGN.md)。

| 阶段 | 交付 | 放行证据 |
| --- | --- | --- |
| M0 · 冻结 | 源码与 Windows 产物分别用本地 annotated tag 固定。从源码标签开独立 worktree 起步，预览入口使用独立端口和状态目录 | 标签 `milestone/pre-hub-0.2.80-source` 和 `milestone/pre-hub-0.2.80-windows` 分别解引用到 `05be7b4` 与 `b2cb3b5`。97 个源码哈希、ZIP 与 EXE SHA-256 均匹配。源代码与安装包在同一个里程碑文档中互相引用。 |
| M1 · Hook、MCP 与数据库 | 冻结事件契约。以 Codex、Claude Code 做两个真实 Hook 适配器，Grok 做能力探针。给中央 MCP 隔离实例加任务写入、查询和持久回执 | 两工具、两授权主机在桌面关闭时都能提交；重复事件或断网补交只入库一次。库中跨工具记录可以按同一个项目查询，账号越权被拒绝。旧 MCP 检索与只读技能查询通过回归。 |
| M2 · 每次提交后的额度查询 | Hook 的每个已确认结果绑定一次额度任务。接入 Codex、Claude Code、Grok 的账号来源，并把 API 产品与订阅额度分清。驾驶舱全局额度页显示周余量、下次周重置、采集时间及状态 | 可支持的真实账号与官方用量逐项一致。每个确认事件都有在其之后发起的查询或显式失败状态；重试、同时使用同账号、时区切换、限流、截止点跨周及登录过期均有测试。没有 Hook 的已配置账号也会按周期刷新。 |
| M3 · 双端定向反馈 | M2 同步交付两端只读任务对话和 mylib 入口，20 窗口巡检输入以 8,000 token 起测。M3 桌面先接源端回执，安卓经真机验收后开放 | 普通终端准备草稿；持久回执宿主绑定一次确认、一次受理。撤权、交接及回执丢失时能核对原请求，非目标输入为零。 |
| M4 · RSI 与版本采用 | 配对回放、受控独立重跑和保留集评测，人工采纳后按兼容范围发布 | 新版实际加载由宿主回执证明。恢复后事件、快照关联和去重一致。证据不足时维持父版。 |

## 回归与隔离验收

各阶段放行前执行[现有功能保护条件](https://github.com/gaoxingkele/mylib/blob/main/tools/agent-hub/rollout-design.md)。记录现役、冻结和候选版本，交叉验证旧客户端与新后台、新客户端与旧后台、新功能关闭及故障时的核心操作，并演练保持现有会话的回退。出现新增回归时停在试点阶段。

- **回馈确认与版本采用。** 同任务两台机器上使用同名窗口；总管聊天、查看建议、取消和确认前会话被替换时，目标输入均为零。仅将确认正文投递给选定执行。RSI 候选通过评测、人工采纳并发布后，新任务可加载指定版本；在途任务经显式操作升级，并回报实际加载版本或待重启状态。

- **桌面与共享终端。** 基线和预览分别运行 `test_desktop_multihost.py`、`test_workspace_relay_refresh.py`、`test_frontend_replay_backpressure.py`。补驾驶舱自动化场景，分别覆盖 DOM 和 WebGL、切换主机、缩窄和恢复窗口、聊天焦点与 Esc、打开或关闭面板。仅面板操作产生的 PTY 输入和 resize 帧均为 0。已有命令、窗口和草稿保留。 [基线测试目录](https://github.com/gaoxingkele/supermonoagent/tree/05be7b4/tests/)
- **采集与授权。** 验证事件来源、同 ID 异文冲突、重复与乱序、离线重试，以及凭据撤销和跨项目拒读。对结果和证据输入验证脱敏、大小边界和记录类型，Hook 凭据限本项目写入，额度采集器限账号快照写入，总管仅查询。 [现有中央 MCP](central-mylib-mcp.md)
- **性能与故障。** 首轮目标为两主机共 20 个观察会话，MCP 入库回执至驾驶舱状态可见 p95 ≤5 秒。分别模拟数据库不可用、进程退出、网络断开和模型限流。测试 Hook 的入队时延与失败隔离，记录积压、重试与拒绝数。额度 API 时延独立观测。
- **额度与隐私。** 在假账号上测试持久回执后触发、同账号并发查询、跨周和失败写回，再对照真实官方结果。失败保留最后一次成功值并显示采集时间与错误状态。区分百分比、积分、精确 Token 和金额，验证模型输入、MCP 请求及日志仅含标准化结果。试点明细按 7 天留存基线核对清理行为。
- **RSI。** 先冻结带标注输入、评分脚本和模型调用预算，再比较同一批轨迹。针对「无输出被误判为阻塞」的候选，要求改动在目标样本触发，配对结果显示误报下降，预留集上无新增误报、无已标注阻塞漏检和无证据结论。记录配对效应、样本量和不确定性。样本不足时留在影子评测。候选启用后可切回父版本配置。
- **退出和回退。** 可独立停用试点 Hook、用量 worker、新增 MCP 能力或桌面驾驶舱。旧终端中继继续提供服务，已确认事件及待处理额度任务在恢复后可追溯。在隔离目录验证冻结公共 ZIP 的安装和启动。

接入试点需要登记两台主机、项目、计费账号映射与可用的官方查询方式。可先用合成数据验证 M1 的契约和失效恢复。终端字节流按需补证，新增跨房间聚合入口独立排期。
