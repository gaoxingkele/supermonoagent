# Codex 风格统一终端

Cursor、Claude、Grok 与 Codex 共用显示基线、代码颜色、本地草稿及历史浏览策略。程序身份、原生按键和权限仍按实际 CLI 处理，显示成 Codex 风格不会把程序变成 Codex。

## 输入

- 原始 CLI 窗口默认处于原始输入状态；点击底部草稿框或打开编辑器后使用本地草稿，也可显式切回原始输入。独立对话记录的观察画面继续只读。
- 输入框贴齐底栏内容区最左侧并加长。项目／交换目录设置移到桌面顶部工具栏，完整路径可从按钮提示或原设置窗口查看。
- 桌面启动目录／连接状态位于上方标签栏，不占底部输入空间。“启动目录”是后台启动会话时记录的路径；项目目录是文件助手的独立设置，不表示 shell 后续 `cd` 的实时目录。缺失或不可用的项目会明确标记。
- 底部输入框与按钮整合为单行高度，多行草稿在框内滚动，不撑高底栏。桌面附件和详细提示可从“附件／展开”查看；安卓“编辑”打开原大输入框，“展开”显示辅助键。已有草稿与附件不因展开收起而清空。
- 本地键入不会逐字发送到远端，网络回显慢时仍可正常编辑草稿。显式“发送”才粘贴；确认新的实时回显后，仅发送一次 Enter。
- 桌面停靠输入框 Enter 发送、Shift+Enter 换行；原有展开长编辑器 Enter 换行，Ctrl+Enter 可显式发送。安卓保留 Enter 发送、Shift+Enter 换行和中文输入法保护。
- “插入终端”继续只粘贴、不按回车。已经插入的同一草稿不会再次被发送按钮重复粘贴；可切换原始输入检查。
- 发送是追加到当前终端输入，不会清空远端已有内容。回显超时、重放、目标切换或连接变化时保留草稿与不确定状态，不自动重试。先检查原始输入再继续。
- “原始输入”是明确的原生交互入口。独立对话记录模式仍保持只读画面，使用原来的结构化提交与保存回执，不能通过原始入口绕过。

附件、文件保存回执与引用保留；未确认保存的附件继续阻止发送。普通文本不依赖目标电脑是否安装文件助手。引用只追加草稿，不自动执行。

## 显示与历史

四类 CLI 使用共同的 Codex 配色、块光标及等宽字体；保留用户字号、实际程序标签、输入建议和有意义的原生警告颜色。高亮只处理有界可见区域，不修改源字节。

滚轮和触摸使用本地历史或历史画面；阅读时新输出不拉动当前位置，回到底部才恢复跟随。Codex 自身的内部翻页只保留在识别为实际 Codex 的显式按钮中，不把其控制码发给其他程序。布局、样式与输入焦点不额外接管终端尺寸，既有空闲租约／当前持有者及服务器确认策略保留。

## 延迟与更新边界

统一界面不能保证消除远端模型、CLI 本身或网络延迟。EWAN 的应用 PING 包含中继及主机队列，不能视为模型响应时间。2026-11-12 的只读对照表明，从本机默认路径到中继的 WebSocket 控制 PING 中位数约180.5ms，绑定本机 WLAN 约48ms；未修改全局路由或中继。

当前已部署 0.2.67 的旧编辑器草稿、选择的文件与回执只在内存中。新版本不能在旧页面卸载后恢复其闭包状态。安装更新会重载界面，安装前请保留旧的未发送草稿及文件引用，完成正在进行的上传。关闭／更新前端不等于结束后台 CLI。
