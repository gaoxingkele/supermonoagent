# 会话记录候选版

本功能仍处于候选版验证阶段，尚未部署到生产服务器或当前设备。

每个后台 CLI 会话对应一个独立记录，桌面和手机查看同一份。关闭查看页面、断网或停止记录器不会证明 CLI 已退出，也不会自动归档。后台读到真实退出后才进入收尾；收尾未完成或采集出错时明确标为不完整。

## 查看与引用

- 底部“历史记录”查看带时间戳的事件、原始终端输出和待确认内容。原始输出默认折叠，完整正文按需读取。
- 底部“对话记录”仅显示已接受的用户输入和已确认的最终回复。来源不明的输入、中间回复、工具输出及推理内容不会冒充已确认对话。
- 弹窗中的“模式：历史 / 对话”切换排列方式，不修改记录。此版本没有思维导图。
- 在记录正文中选择文字后，可复制，或引用到发起查看的窗口草稿。引用保留原草稿，不向终端写入、不自动按 Enter；目标窗口、连接或身份变化时拒绝引用。
- “代码：折叠”需要明确绑定且健康的语义来源。折叠显示只影响阅读层，原始终端持续接收原字节；随时可选“原始终端”。来源异常时恢复原始终端。
- 记录更新会保留当前选择与阅读位置；阅读较早内容时提示有新记录，不强制跳页。

## 来源支持边界

“绑定对话源”由主机所有者明确选择精确来源 ID，绑定到本次后台进程代次。不会根据目录、窗口标题或最近修改时间猜测。绑定从当前时点开始，选择来源不隐含导入其全部旧对话。

当前已验证 Codex 0.167.0 的匹配版本私有快照只读接口。未知版本、未知来源或未证明的人类输入会显示限制；不会通过读取日志启动模型或恢复提供商会话。

Claude 原生 Stop/日志目前只能提供候选回复，无法可靠证明最终结论。因此其候选内容保留在历史中，完整自动对话捕获仍有待确定独立结构化记录模式，不能把当前候选版描述为 Claude 完整支持。

## 本地保存

主机状态目录下的 `journals/` 为私有存储，每个会话保存一个 `<journal_id>.history.sqlite`，采用 SQLite WAL 和 FULL 同步。原始字节不因折叠或终端内存历史裁剪而删除；故障或超出有界队列容量时记录可见的缺口。

后台会话归档后派生 `<journal_id>.conversation.jsonl` 与 Markdown 对话文件。它们只包含符合证据条件的输入与最终回复，原始内容仍在 SQLite 中。记录器重启不能把仍活着的 CLI 标成正常结束。旧后台可使用只读 companion 采集，其初始回放明确标记为部分覆盖；当前 companion 不隐含完成生产安装或服务器同步配置。

Windows 目录与文件权限限制为当前用户和 SYSTEM；POSIX 目录/文件分别为 0700/0600。原始输出可能包含用户主动打印的敏感内容，因此不能公开上传记录目录。

## 服务器同步与运维

服务器使用同一 HTTPS 中继域名下独立的 `/journals/ws` 服务，已有终端中继不解码记录协议。服务部署与鉴权格式见 [部署说明](../deploy/journal/README.md)。现有 SSH 管理通道不可用，候选版没有执行生产部署。

主机私有 `journals/mirror-config.json` 可显式配置 schema=1 的 routes，每项包含 `local_owner_scope`、`local_room`、`destination`、`credentials`。destination 按冻结协议包含 destination_id、authority、service_path、owner_scope、external_room；host_installation_id 和 source_epoch 由主机写入。credentials 为独立的 token、host_secret 与可选 enrollment_key，不能放入页面、公共仓库或命令行。每份记录只允许固定到一个目的地。主机的本地房间名不会自动被当成外部中继房间。

只有全部引用内容和事件已持久提交、哈希验证完成后，服务器才返回绑定目的地与连续序号的回执。“服务器已确认”仅代表对应序号已复制；不会清除原采集缺口，也不等于来源完整。断网保留待同步批次。未配置同步不能显示为已经存入服务器。

编译后的公共程序提供 `journal-companion`、`journal-service`、`journal-hook` 模式；开发环境可使用对应 Python 模块。仅查看各模式 `--help` 不会启动用户 CLI。安装、来源绑定、生产同步和跨设备验收须分别验证。
