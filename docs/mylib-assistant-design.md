# mylib 右侧助理栏方案

状态：开发与验收中。侧栏、本地技能匹配、故障线索建议及目标项目账本只读接口已实现并通过定向验证；外部模型、账本写入和打包发布仍未完成。

## 目标和界面

在现有 Windows 工作区右侧增加可折叠、可调整宽度的「mylib 助理」栏，随当前活动终端切换。顶部显示电脑、房间、窗口及上下文更新时间；提供「技能建议」「进化建议」「对话」三个视图。窄窗口使用抽屉，避免挤坏终端布局。展开后沿用终端现有尺寸协商机制，不抢占其他客户端的尺寸控制权。

建议卡显示名称、推荐原因、相关输出片段、技能源文件、支持的智能体，以及查看说明、复制调用指令、忽略操作。第一阶段不自动向正在运行的终端输入命令。

## 已核实的接入点

- `src/supermonoagent/static/workspace.js` 的 `window.smaWorkspace` 提供 activeSession、activePane、activeHost、terminal；pane 包含 host、raw、generation。可读取 xterm 已解析缓冲区，避免解析页面截图或将 ANSI 原始流直接交给模型。
- 同文件已有 host generation 和 livePane 等生命周期校验。分析请求和返回结果应绑定 host/session/generation/context revision，避免切换窗口或重连后展示错误建议。
- 技能维护源为 `D:/aicoding/mylib`；入口为 README.md、WIKI.md，运行时清单为 `skill-runtime/manifest.json`。这些提供候选目录，具体能力与调用方式仍以对应 SKILL.md 为准。
- `D:/aicoding/mylib/skills/meta-rsi/SKILL.md` 定义证据账本、tick、signal、idea、trial、shadow、propose、decide；工具不调用模型。项目状态保存在对应项目 `.metarsi/`，不能写入共享技能目录。受保护变更必须走准入，decide 需要明确用户指示。

## 推荐实现

复用现有 HTML/JS 工作区、Windows WebView 外壳和 Python 后端。增加独立的助理模块及经过鉴权的结构化请求通道，不把助理数据作为 PTY 输入输出传输。不新增依赖作为第一版前提。

1. 上下文采集：默认只读当前终端最近有限输出，例如 200 行且最多 32 KiB；记录来源窗口和时间。输出变化合并处理，在空闲后分析，支持暂停和手动刷新；相同上下文去重。终端内容是不可信数据，不能作为助理的系统指令。Token、密码及未提交输入不作为主动采集对象；脱敏不能保证发现所有秘密，外部模型发送需有清晰可见的设置。
2. 技能检索：后端按维护清单建立名称、description、来源、适配器的本地索引。先用关键词规则获取少量候选，再由配置的模型结合上下文排序和解释；按需读取技能正文。没有模型配置时仍可提供基础匹配，并明确标记能力范围。
3. 模型服务：独立配置服务地址、模型及凭据；中继 Token 仅用于连接鉴权，不能当作模型 API Key。现有 Codex/Claude 终端登录状态不等于可直接复用其模型接口。远程模型凭据不下发给页面。
4. metaRSI：先读取当前项目的账本和模式，展示失败信号、已否决方案、待验证影子规则。重复失败只能成为建议线索，不能冒充已验证结论。新项目未初始化时显示未启用，不自动为所有远程项目初始化。登记操作由目标电脑上的后端执行，项目根目录来自可信会话元数据或用户指定，不能相信终端文本中的路径。
5. 跨电脑：分开显示「助理所在电脑的 mylib」与「目标电脑可用技能」。本机路径不能直接交给远端执行；远端需声明技能清单及项目元数据能力。旧后端只支持查看建议和复制指令。中继用于转发，不假定它安装了 mylib 或掌握项目目录。
6. 存储：助理偏好、忽略记录与摘要按电脑和会话隔离；metaRSI 实验记录保持在目标项目的原生账本中。技能源码保持唯一维护源，不复制成另一个可编辑技能库。

## 分期及验收

- 第一期：侧栏、窗口绑定、上下文预览、基础技能匹配、来源链接和复制指令。验收窗口切换、重连、关闭、折叠与尺寸变化，不向任何用户 PTY 注入输入。
- 第二期：可配置模型分析、上下文去重、取消请求、错误提示与成本限制。验收旧结果不会覆盖新窗口、凭据不进入日志、无模型时可降级。
- 第三期：读取并展示 metaRSI 模式，登记建议及实验产物，连接验证结果。验收项目隔离、缺失账本提示、受保护变更不能绕过准入。

当前新版后台通过 OP22 提供目标终端启动目录、目标技能清单及固定账本页面；只对后台所有者开放，异步读取后再核查会话与权限。目录是终端启动目录，不跟踪 shell 内后续 cd；旧后台没有该能力时仍可显示本机技能建议。测试见 `tests/test_assistant_context.py`、`tests/test_daemon_assistant_context.py`、`tests/test_workspace_tab_picker.py`。不从页面文字推断模式，不将故障线索视为验证证据，不自动执行 propose/decide。

后续开发源码已增加 provider-neutral 模型配置：五个非凭据字段（入口、模型名称、服务地址、自动附带上下文、字符上限），受同源原生接口保护，按启动状态目录隔离、原子保存。损坏配置只返回默认值，不自动覆盖原文件；拒绝密钥字段、URL 凭据和非 loopback 明文 HTTP。配置界面不发模型请求，实际调用仍待入口选择与适配。此增量未随 0.2.37 发布，不将保存偏好称为已配置模型服务。

source_path: `src/supermonoagent/assistant_preferences.py`, `src/supermonoagent/desktop_assistant.py`, `tests/test_assistant_preferences.py`, `tests/test_assistant_preferences_ui.py`

独立文件与助理任务使用每连接有界队列及专用执行器，避免慢文件系统拖住终端输入和心跳。原生 WebView2 已使用测试剪贴板源验证建议显示及上传桥接，证据为 `.omx/artifacts/file-paste/native-webview-evidence.json`；不以此替代真实系统剪贴板验收。目标电脑尚未使用新后台、未配置 mylib 或模型服务时，不能宣称这些能力已在该电脑上线。
