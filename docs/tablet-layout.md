# Android 平板横竖屏适配

状态：用户已停止本轮设备调试，当前作为 WIP 备份保存。待修事项：历史工具栏仍为 38px（低高度时 32px），未达到 44px 目标；低高度视口的历史返回条／提示条可能覆盖页头控制按钮。补强后的平板触摸高度测试会失败，候选不能标为完成或直接发布。

本次针对荣耀 ROD2-W09 平板：ADB 实测物理分辨率 1920×3000、密度 400dpi、Android 16。适配候选为 Android **0.2.71 / 构建 73**；0.2.70 是本轮早期构建。设备实际可用视口仍受系统栏和输入法影响，程序按实际字格及可用空间计算行列，不硬编码特定型号或分辨率。

## 使用方式

进入终端后点击 **适配本屏**。程序沿用既有终端尺寸接管流程；获得后台确认后，竖屏利用高度显示更多行，横屏利用宽度显示更多列，并随旋转自动调整。字号保留用户选择，接管时采用自然行距，不通过缩小字体挤入内容。

点击 **跟随电脑** 可释放本屏适配。跟随状态仅查看和旋转不会抢走电脑的尺寸控制；明确适配会同步改变该共享终端的行列数，其他观看端会跟随。已有手机上的“接管 / 跟随”行为保持不变。

大屏顶部、辅助键和输入栏使用至少 44px 触摸高度；宽屏辅助键复用单行布局，终端选择、设置和编辑弹窗使用更宽的有界尺寸。平板身份依据完整 CSS 屏幕短边至少 600px，输入法缩小可视区域时仍保留平板布局。

## 历史与验证

保留既有最多 20,000 行本地 scrollback，以及尺寸切换前的历史归档。没有创建第二个实时终端解析器，也不伪造源主机已经丢失的历史。ConPTY 在扩大终端时可能为保持真实光标位置追加空尾行；最新页保留这一状态，翻看顶部和中段时可使用完整高度显示历史。

`tests/test_android_tablet_layout.py` 在修改前复现平板入口缺失，修复后 DOM / WebGL 通过。测试采用 768×1200、1200×768 和 DPR 2.5：

- 竖屏约 96×56、横屏约 152×31，回竖恢复 96×56；保持 14px 字号及自然行距。
- 6500 行编号历史首尾、顶部与中段密集显示、未发送草稿在旋转后保留。
- 跟随旋转不产生尺寸或终端输入帧；明确适配后后台和本地解析网格一致。
- 弹窗不越界，模拟输入法缩小视口仍按平板处理，无终端输入。
- 初步的平板、全屏适配、接管/跟随、历史交接、手机及跨端布局组合检查曾有 10 项通过，历史可见密度检查也通过。后续审查补入历史工具栏 44px 触摸高度断言，当前测试复现上述未完成问题；不能将初步通过结果视为最终验收。

数值、截图和 ConPTY 对照：`.omx/artifacts/android-tablet-layout/`。`dom-portrait-history-middle.png` 与 `dom-landscape-history-middle.png` 展示密集历史；这是桌面 Chromium 移动模拟验证。
