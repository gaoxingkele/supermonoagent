# 多电脑连接与凭证边界

当前更新（2026-10-24）：用户最新选择为 Token＋房间号，统一邮箱账号不再是交付前提；[统一中继账号配置](relay-account-setup.md) 保留为高级功能说明。生产 HTTPS/WSS 和签名更新已部署，但真实 WSS 目录能力仍报告 `host_enrollment:false`，独立房间所有权的严格生产迁移尚未执行。证据：`.omx/artifacts/goal-completion-audit/production-directory-capabilities.json`。取消邮箱账号不等于取消独立 owner secret 的边界。

本轮 TD-006 使用每台电脑独立授权、已知房间订阅的模型。实现证据见 `src/supermonoagent/security.py`、`relay.py`、`daemon.py`、`static/workspace.js` 与 `android/assets/mobile/app.js`；协议见 [protocol.md](protocol.md)。生产中继已部署兼容 Token 发现能力，不能据此声称严格所有权登记已迁移。

## 连接与身份

- 每个保存的工作区绑定连接端点与房间码，并保存自己的访问凭证。修改端点或房间码会清除旧凭证及旧电脑状态。会话、窗口和分组的客户端键使用 JSON 元组，不能通过冒号拆分；线上仍发送原始会话 ID。
- 桌面保持多台电脑的独立连接、目录、尺寸租约、速率与重试。Android 并行保持目录，输出只订阅当前活动终端；进入后台关闭连接，恢复后重新认证和订阅。
- 终端访问 Token 代表一台电脑上的权限，不代表全局身份，也不允许注册该电脑的 relay 房间所有权。所有权使用独立高熵 secret；中继只持久化 SHA-256 验证值。默认没有全局共享 Token。
- 已知房间发现要求每个房间提供有效访问 Token。错误凭证、未知房间和无法验证的离线房间都返回不可用，不公开全部房间、机器名或项目名。订阅目录推送，不轮询 `/health`；health 仅表示服务存活。

## 凭证保存与传输

浏览器启动凭证放在 fragment，页面读取后清除地址中的凭证；WebSocket 地址不带 Token 查询参数，认证通过首帧 HELLO 或中继加入消息。会话存储为默认；桌面用户明确勾选记住时可保存到本机浏览器存储。Android 保存的连接配置属于应用本地数据。这些存储不是操作系统凭证保险箱，设备账户和浏览器配置应受到保护。

非 loopback 上联必须使用 `wss://`。公开监听要求证书与私钥，或显式配置可信 HTTPS 反向代理及允许的精确 Origin。HTTP Host 与浏览器 Origin 都经过校验，不接受全局 `null` Origin。原生客户端无 Origin 时仍必须认证。测试证书只用于隔离测试，不得用于生产。

## 部署迁移

1. 在中继电脑运行 `supermono-relay --enrollment-file <私有验证文件> --enroll <房间码>`，取得一次输出的 owner secret，安全交给对应主机管理员。已有房间不能被覆盖注册。
2. 主机用 `--relay-owner-secret` 配置这个独立 secret；已有其他中继配置须分别登记所有权。不要把 owner secret 当作终端访问 Token 分发。
3. 为中继与需要公开的 daemon 配置 `--tls-cert`、`--tls-key`、`--allowed-origin https://对应域名`。若 TLS 在受信反向代理终止，使用 `--reverse-proxy-tls` 和精确 `--allowed-origin`，并限制后端只接受该代理的流量。程序不能自动保证代理网络隔离。
4. 更新客户端保存的端点为 HTTPS/WSS，并逐电脑输入访问 Token。旧中继不支持目录推送时，已保存电脑仍可直接连接，但不会具备新版目录鉴权和所有权登记；不能据此宣称生产安全升级已完成。

`--development` 仅用于明确的 loopback 测试。生产升级需要选择维护窗口；本次未重启现有 daemon、Kimi、Codex 或远程中继。

## TD-006G：后续统一身份与分发设计

统一身份采用授权控制面，不合并现有主机访问 Token。建议让用户设备生成独立密钥，通过一次性、短时配对码向每台主机申请授权；主机签发限定主机、账户、权限与到期时间的短期会话凭证。控制面只保存设备公钥、授权记录和撤销版本；私钥与主机长期凭证不离开各自设备。

新增设备必须经过对应主机管理员确认；中继房间登记仍用独立 owner secret。撤销设备应递增主机授权版本，立即关闭已认证连接、清理待发队列与目录授权，并阻止旧凭证重连。凭证刷新需绑定设备证明，不能仅凭长期 bearer Token 跨主机刷新。离线主机恢复后先同步撤销版本，再接收受控会话。

以上统一账户、设备签名与短期凭证是设计方案，尚未实现，也不属于本轮以“设计”为交付物的 TD-006G 的上线声明。本轮已实现每主机独立凭证、端点绑定和访问 Token 撤销，避免为了方便而引入全局明文共享密钥。

## 资源测量边界

可复现脚本 `scripts/benchmark-global-workspace.py` 使用 loopback、合成 PTY，测量 1/4/16 个主机。应用心跳往返分别 40/160/640 字节，按 15 秒间隔约 2.67/10.67/42.67 B/s；没有打开的终端输出订阅为零。结果见 `.omx/artifacts/global-workspace/resources.json`。

Python 内存测量包含合成主机、中继和客户端，不是 Android 堆内存，也不是每个真实电脑的后台成本。真机后台关闭连接降低网络唤醒；尚未进行长时间射频功耗、系统电池统计或公网弱网续航实验，不能把应用消息字节数等同于耗电量。
