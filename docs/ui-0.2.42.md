# 界面更新 0.2.42：安卓接管与跟随

2026-10-25 已发布当前 Windows／Android 完整界面快照，序号 `1792917931547497`。两端均通过现有“检查界面更新”下载并重载，无需安装 APK 或更新 Windows 原生壳。没有修改、重启现有 daemon 或 relay，没有操作用户终端。

## 两种模式

| 操作 | 尺寸与显示 | 输入 |
| --- | --- | --- |
| 点击“接管” | 手机获得尺寸控制；按可用宽高、字号及旋转调整终端网格，保留高亮 | 正常输入 |
| 接管后点击“跟随” | 手机释放尺寸控制；在线桌面恢复自身当前适配尺寸，手机保留远端行列网格及可读字号，可左右拖动 | 正常输入，不因按键抢回尺寸 |

按钮显示的是下一步操作：接管后显示“跟随”，释放后显示“接管”。模式切换不改变 DOM／WebGL 渲染设置，两者都在手机本地绘制终端，不是桌面截图或像素镜像。

若没有在线、可见且可正常调整尺寸的远端桌面，释放后不猜测或强行恢复一个历史宽度；保持当前已确认网格并提示等待远端接回尺寸控制。跟随时调整手机字号或旋转不会改变共享 PTY 尺寸。可选缩小总览仍保留；显式切换“跟随”回到可读字号、可横向拖动的显示。

## 原因与修复范围

- 原 Android `#control` 无论当前状态如何都发送 `take_control:true`，因此“主控”只是再次接管，没有释放分支。
- 复用旧后台已有的订阅租约机制，在同一有序连接上移除、恢复当前订阅来释放控制；等待后台确认，抑制旧 ownership 状态触发自动重抢。不新增后台协议或依赖，不关闭终端。
- 复用现有回放恢复逻辑，对相同快照避免重置解析器；不同快照仍按现有规则恢复，不承诺保留已经丢失的旧输出。
- 序列化模式切换与手动刷新，避免旧协议缺少快照关联 ID 时两个操作争用同一回放。连接、主机、会话或 generation 改变时丢弃旧操作。
- Windows 的已完成尺寸请求缓存未清除，完全相同的第二轮交接会被去重。只在匹配的尺寸确认后清除 `lastAttempt`，保留原超时／ACK／尺寸限制处理。

产品修改仅 `android/assets/mobile/app.js`、`android/assets/mobile/index.html`、`src/supermonoagent/static/workspace.js`；新增行为回归 `tests/test_android_control_follow.py`。总览十六宫格、0.2.41 高亮与灰色推荐文字均保留。进行中的文件交换模块没有进入本次更新包。

- 真实隔离桌面／手机页面验证重复交接、触摸横拖、跟随时字号／旋转不 resize、辅助方向键输入、无桌面时等待；测试只操作自有模拟 PTY。
